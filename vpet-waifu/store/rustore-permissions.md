# RuStore — «Запрашиваемые данные» и «Чувствительные разрешения»

Готовые ответы для двух полей анкеты. Всё сверено с релизной сборкой
(`aapt2 dump badging`), а не с памятью о том, что там должно быть.

---

## Запрашиваемые данные — ничего не выбирать

Оставить **0 / 38**. Приложение не собирает и не передаёт никаких данных, и это
не декларация, а свойство сборки:

- **Нет разрешения `INTERNET`.** Без него процесс физически не может открыть
  сетевое соединение — куда бы данные ни собирались, отправить их некуда.
- **Нет SDK аналитики и краш-репортинга.** Ни Firebase, ни AppMetrica, ни
  Crashlytics, ни Sentry — в зависимостях пусто.
- **Нет аккаунтов и регистрации.** Сохранение лежит в приватном хранилище
  приложения; экспорт делает сам пользователь в файл, который остаётся у него.

Проверить можно так:

```bash
aapt2 dump badging app-release.apk | grep uses-permission   # INTERNET отсутствует
```

## Чувствительные разрешения — текст для модератора

Скопировать в поле «Обоснование» как есть:

> **SYSTEM_ALERT_WINDOW** — разрешение используется для дополнительной функции
> «плавающий питомец»: по желанию пользователя персонаж отображается небольшим
> окном поверх других приложений, его можно перетаскивать по экрану и
> взаимодействовать с ним (покормить, погладить, уложить спать), не открывая
> приложение. Функция выключена по умолчанию и включается вручную в настройках
> приложения; там же её можно выключить в любой момент. Окно показывается
> только по явному действию пользователя, не перекрывает системные диалоги и не
> используется для рекламы, наложений поверх других приложений с целью обмана
> или сбора ввода.
>
> **POST_NOTIFICATIONS** — уведомления сообщают об игровых событиях, которые
> происходят по таймеру, пока приложение закрыто: закончилась рабочая смена
> персонажа, персонаж проголодался. Все уведомления локальные, формируются на
> устройстве; push-сервисы и сеть не используются. Уведомления по желанию
> отключаются в настройках приложения.
>
> Приложение не запрашивает разрешение `INTERNET` и не имеет технической
> возможности передавать данные куда-либо за пределы устройства.

## Про `ACCESS_NETWORK_STATE`, если модератор спросит

Оно есть в списке разрешений сборки, но **мы его не объявляли** — оно приходит
транзитивно из библиотеки `androidx.work` (WorkManager), которая используется
для локальных отложенных задач: пересчитать состояние персонажа и обновить
виджет. Само по себе оно даёт только чтение статуса сети (есть подключение или
нет) и не даёт доступа к самой сети. Без `INTERNET` использовать его для
передачи данных невозможно.

Полный список разрешений релизной сборки:

| Разрешение | Зачем |
|---|---|
| `SYSTEM_ALERT_WINDOW` | плавающий питомец (по желанию) |
| `POST_NOTIFICATIONS` | локальные уведомления об игровых событиях |
| `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SPECIAL_USE` | сервис, который держит плавающее окно |
| `RECEIVE_BOOT_COMPLETED` | восстановить локальные напоминания после перезагрузки |
| `VIBRATE` | тактильный отклик на нажатия (отключается) |
| `WAKE_LOCK` | транзитивно из WorkManager |
| `ACCESS_NETWORK_STATE` | транзитивно из WorkManager, см. выше |
